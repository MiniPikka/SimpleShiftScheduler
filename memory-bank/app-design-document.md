# 倒班助手 App 设计文档

## 1. 概述

**应用名称**：倒班助手
**平台**：Android
**功能简介**：
用于帮助用户管理和查看倒班信息，支持周期设置、班组管理、日历展示及统计功能。

---

### 2.2 倒班日历

**功能**：独立页面，通过首页"📅 日历"按钮跳转进入。按日历展示本月倒班情况，可切换班组并统计班次数量。

**界面结构**：
- 顶部 TopAppBar（返回箭头 + 标题"倒班日历"）
- 班组下拉框
- 月份导航栏（上月/下月 + 今天按钮 + 统计按钮）

**界面元素**：

* **7×7 日历表**：

  * 第一行显示周日到周六
  * 其余行显示当前月日期及补全的前月/下月日期
  * 每个格子包含两行：

    1. 日期
    2. 班次类型（早、中、休、夜、学习班）
* **左上角班组切换下拉框**：用于切换不同班组
* **右上角统计按钮**：统计当前班组在当月早、中、休、夜、学习班的天数

### 2.3 倒班规则设置

**功能**：用户自定义倒班周期、班次规则及默认班组。

**界面元素**：

* 周期长度设置
* 每一天班次设置
* 默认班组选择
* 保存并应用按钮

**操作流程**：

1. 用户选择周期长度
2. 设置每天对应班次
3. 选择默认班组
4. 点击保存，系统应用规则

### 2.4 日历提醒

**功能**：为每个班次类型设置独立的提醒时间，通过系统日历日程实现。

**界面元素**：

* 提醒设置在设置页"倒班规则设置"中，位于班组选择下方
* 每个班次类型（早/中/休/夜/学）一行，显示当前提醒时间或"未设置"
* 点击行弹出 Material3 `TimePicker` 时钟表盘（24 小时制，V2 Design Token 主题一致）
* 已设置提醒的班次可点击"关闭提醒"按钮（红色）删除

**提醒策略**：

* 使用 Android Calendar Provider（`CalendarContract`）写入设备本地日历日程
* 每次设置变更后自动同步未来 365 天（一整年）的日历日程
* 日程持久化在系统日历数据库，设备重启自动恢复
* 应用回到前台时重新同步（处理时区变更）
* 使用默认班组计算班次日期
* 每个日程设置准时提醒（`METHOD_ALERT`），系统自动弹出通知
* 使用本地日历账户（`ACCOUNT_TYPE_LOCAL`），日程不依赖 Google 账户、不同步云端

**跨品牌兼容性**：

* Calendar Provider 是 AOSP 标准 API（API 14+），所有 Android 品牌必须支持
* 小米 MIUI、华为 EMUI/HarmonyOS、OPPO ColorOS、Vivo OriginOS、三星、原生 Android 全兼容

**权限需求**：

* `READ_CALENDAR`：读取系统日历（查询现有日程）
* `WRITE_CALENDAR`：写入/修改系统日历日程

### 2.5 桌面小组件（V2 深色主题）

**功能**：在设备桌面显示今日班次信息，无需打开 App 即可查看。V2 升级为深色主题，新增明日班次预览和休息倒计时，与 App 内 V2 Design Token 对齐。

**界面结构**（V2 深色主题）：

```
┌──────────────────────────────────────┐
│  ┌───────┐                           │
│  │  早   │  一值          距休 2天   │  深色背景 #1B1F26
│  │ 白字  │  第 10/42 天              │  白色/灰色文字
│  └───────┘                           │
│                                      │
│  5月17日 周三          ● 明日: 中    │  日期 + 明日预览
└──────────────────────────────────────┘
```

**界面元素**（V2）：

* **深色背景**：`#1B1F26`（对齐 App V2 卡片表面色），全 Widget 统一暗色调
* **班组名称**：白色中号文字，`#F5F7FA`
* **日期标签**：格式 `M月d日 周X`（如"5月17日 周三"），灰色小字，`#9CA3AF`
* **今日班次徽章**：圆角 10dp Box + 班次强调色背景 + 20sp Bold 白字（早=橙 `#FFB347`、中=蓝 `#4DA3FF`、休=绿 `#35D07F`、夜=紫 `#7C5CFF`、学=黄 `#F2D94E`）
* **周期进度**：文字"第 X/Y 天"（灰色小字，Glance 不支持进度条组件）
* **休息倒计时**：
  - 今日休息 → 绿色 Bold "休息日"
  - 距休 1 天 → 绿色 Medium "明天休息"
  - 其他 → 灰色"距休X天"
* **明日预览**：6dp 彩色圆点（班次颜色）+ "明日: " + 班次标签（灰色 + 白色）
* **未配置状态**：白色 Bold "未配置" + 灰色"请先设置排班规则"（替代旧版误导性的 "?" + 绿色 REST）
* Widget 尺寸：4×1（`targetCellWidth=4`, `targetCellHeight=1`）

**交互**：

* 点击 Widget 任意位置 → 打开 App 首页
* Widget 每 1 小时自动刷新
* App 内修改设置后 Widget 立即更新（含快照比较去重：设置未变化时跳过更新）

**技术方案**：

* 使用 Jetpack Glance 框架（Compose 式 Widget API）
* 直接从 DataStore 读取倒班配置，调用 domain 层 `computeWidgetShiftData()` 计算今日数据 + 明日数据
* 颜色以 `Color(0xFFxxxxxx)` 内联在 `ShiftWidget.kt` 中（Glance 不支持资源引用和主题系统）
* 进度使用纯文字"第 X/Y 天"（Glance 不支持 `LinearProgressIndicator`、`fillMaxWidth(fraction)` 等 Compose 特性）
* 徽章使用 `Box` + `cornerRadius(10.dp)` + `background(accentColor)`（Glance 无 `CircleShape`）
* 实例复用：`ShiftWidget` 作为 Activity 的 `val` 单例，避免每次更新的对象分配
* 无需额外后台服务，利用系统 Widget 更新机制

### 2.6 拼假神器（差异化核心功能）

**功能**：自动分析今日至年底的最佳请假方案，结合用户的倒班表 + 法定节假日，找到"请最少假、连休最久"的策略。不跨年，日期显示清晰无歧义。

**核心价值**：倒班人员的妻儿老小遵循正常节假日作息。拼假神器帮助用户用最少的年假，在家人放假时最大化团聚时间。

**界面结构**：

```
┌──────────────────────────────────────┐
│  ← 拼假神器                           │  TopAppBar
├──────────────────────────────────────┤
│  基于你的倒班表 + 法定节假日             │  说明文字
│  帮你找到最佳请假方案                    │
├──────────────────────────────────────┤
│  ┌──────────────────────────────┐    │
│  │ 🏆 最佳方案                    │    │  高亮推荐卡片
│  │ 请假 2 天 → 连休 6 天          │    │  (金色边框)
│  │ 6月15日 — 6月20日              │    │
│  │ 含端午节假期 🎋                 │    │  节日标识
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 1 天 → 连休 4 天          │    │  常规策略卡片
│  │ 5月16日 — 5月19日              │    │  (按效率降序)
│  │ 含周末                         │    │
│  │ 效率: 4.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 3 天 → 连休 9 天          │    │
│  │ 9月30日 — 10月8日              │    │
│  │ 含国庆节假期 🏛                │    │
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│  ...                                 │
└──────────────────────────────────────┘
```

**界面元素**：

* **顶部说明区**：简短说明功能用途（基于倒班表 + 法定节假日）
* **策略卡片列表**（按综合评分降序）：
  * 请假天数 → 连休天数（大字体，核心信息）
  * 具体日期范围：连休起止日
  * 节日/周末重叠标识（如"含端午节假期 🎋"、"含周末"）
  * 效率标签（连休 ÷ 请假 = X倍）
  * 最佳方案卡片有金色边框高亮
* **筛选选项**（可选，二期）：
  * 最多请假天数滑块（默认 5 天）
  * 仅看含节假日方案 toggle

**算法核心逻辑**：

1. 生成未来 365 天每日状态（班休 + 节假日 + 周末）
2. 识别所有"休息块"（连续休班日）和"工作间隙"（两块休息之间的连续工作日）
3. 对于每个 ≤ 最大请假天数的工作间隙：请假桥接 → 两边休息块 + 间隙 = 一个长连休
4. 额外检测：请假延伸现有休息块（在休息块前后请 1~N 天）
5. 综合评分：
   - 效率分：连休天数 ÷ 请假天数（权重 50%）
   - 长度分：连休绝对长度（权重 25%）
   - 家庭分：与节假日/周末的重叠天数（权重 25%）
6. 去重（同一连休区间的策略保留最优）、按评分降序排列

**法定节假日数据**：

* 内置中国国务院发布的法定节假日（元旦、春节、清明、劳动节、端午、中秋、国庆）
* 包含调休工作日（如周末补班），确保计算准确
* 数据文件 `domain/holiday_data.kt`，每年更新一次
* **分析范围**：今日至当年 12 月 31 日（不跨年，避免年份混淆）

**技术约束**：

* 纯 domain 层计算（所有函数可独立单元测试）
* 不依赖网络请求（节假日数据本地内置）
* 支持自定义周期和参考日期（复用现有 `customCycle` + `referenceDate`）

### 2.7 同事模式（社交裂变功能）

**功能**：输入两个人的班组，自动计算下次同时休息日期、共同休息天数。情侣、朋友、同事都会用，传播力极强。

**核心价值**：不同班组的倒班人员休息日不同。同事模式让两个人一眼看到"我们什么时候能一起休息"，解决社交协调痛点。结果截图即内容，天然适合社交传播。

**界面结构**：

```
┌──────────────────────────────────────┐
│  ← 同事模式                           │  TopAppBar
├──────────────────────────────────────┤
│                                      │
│  我是                   他是           │
│  [一值 ▼]              [三值 ▼]       │  双班组下拉框
│                                      │
├──────────────────────────────────────┤
│  ┌──────────────────────────────┐    │
│  │       下次同时休息               │    │  主结果卡片
│  │         5月28日                 │    │  大字体日期（36sp Bold）
│  │         星期三                  │    │
│  │       距今 14 天                │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌────────────┬────────────┐         │
│  │ 未来30天    │ 未来60天    │         │  统计卡片行
│  │  共同休息   │  共同休息    │         │
│  │   3 次     │   7 次     │         │
│  └────────────┴────────────┘         │
│                                      │
│  共同休息日列表                        │
│  ┌──────────────────────────────┐    │
│  │ 5月28日 星期三               │    │
│  │ 6月03日 星期二               │    │
│  │ ...                          │    │
│  └──────────────────────────────┘    │
│  分析范围：2026/05/14 — 12/31         │
└──────────────────────────────────────┘
```

**界面元素**：

* **双班组选择区**：两个并排下拉框（"我是"和"他是"），切换即时刷新
* **主结果卡片**（核心视觉焦点）：大字体"下次同时休息"日期 + 星期 + 倒计时，渐变背景
* **统计卡片行**：未来 30/60 天共同休息次数
* **共同休息日列表**：可滚动日期列表，每行显示日期 + 星期
* **底部**：分析范围说明（今日至年底）

**算法**：

对分析范围内每一天，分别计算两个人的班次：
```
isRestA = (shiftA == REST || shiftA == STUDY)
isRestB = (shiftB == REST || shiftB == STUDY)
if isRestA && isRestB → 共同休息日
```
O(n)，n ≤ 365。纯函数，可独立单元测试。复用 `getShiftTypeForDate()` 和 `teamPhaseOffsetFor()`。

**社交传播设计**：

* "下次同时休息"是大字体具体日期，天然对话素材（"我们 5 月 28 日可以一起休息！"）
* 结果页面信息密度高，截图即社交分享内容
* 两个人一起看屏幕时，主卡片视觉冲击力强
* V2 可加入分享按钮（生成带二维码的分享图）

**技术约束**：

* 纯 domain 层计算，复用 `getShiftTypeForDate()` + `teamPhaseOffsetFor()`
* 分析范围：今日至当年 12 月 31 日（与拼假神器一致，不跨年）
* 班组下拉框复用 `TeamDropdown` 组件

### 2.8 倒班津贴（高频刚需功能）

**功能**：输入各班次补贴金额（早/中/夜/学各可设），自动统计当月各班次天数，精确计算本月倒班津贴。支持"如果多上 X 天某班次"的假设分析。只算倒班直接决定的收入——算得准、零维护、普适所有企业。

**核心价值**：倒班津贴是唯一完全由倒班表决定的收入。用户每次换班/加班前都会想"这样能多拿多少"，打开 App 就能看到答案。高频刚需，计算 100% 准确。

**界面结构**：

```
┌──────────────────────────────────────┐
│  ← 倒班津贴                           │  TopAppBar
├──────────────────────────────────────┤
│  ⚙️ 津贴设置                          │  可折叠设置区
│  班次补贴（每班额外金额）               │
│  早班 [0]   中班 [50]                 │
│  夜班 [200] 学班 [0]  元/班           │
├──────────────────────────────────────┤
│  5月 · 一值                           │  当前统计月
│                                      │
│       本月倒班津贴                     │
│       ¥1,750                          │  大字体金额
│                                      │
│  班次统计                             │
│  早班 8次 · 中班 7次 · 夜班 7次       │
│  休班 8次 · 学班 1次                  │
│  夜班 ¥1,400 · 中班 ¥350             │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 💡 如果多上 [2] 天 [夜班 ▼]    │    │  假设分析
│  │ → 津贴 +¥400                  │    │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘
```

**界面元素**：

* **津贴设置区**（可折叠）：
  * 班次补贴：早/中/夜/学各一行，每班额外金额（默认全 0，支持小数如 12.5 元）
  * 输入支持小数点（整数部分最多 4 位，小数部分最多 2 位）
  * 部分输入（如 "5."）不会丢失——显示文本与解析值解耦，保持编辑流畅
* **当月津贴主卡片**：
  * 大字体"本月倒班津贴"金额（核心视觉焦点）
* **班次统计区**：
  * 自动统计当月各班次天数（从倒班表计算）
  * 各班次贡献明细（夜班 7次 × ¥200 = ¥1,400 · 中班 7次 × ¥50 = ¥350）
* **假设分析卡片**：
  * 天数和班次类型均可选
  * 实时显示津贴增量

**算法**：

```
1. 统计当月各班次天数：
   早班 M 次、中班 A 次、夜班 N 次、休班 R 次、学班 S 次

2. 本月倒班津贴 =
   早班补贴 × M + 中班补贴 × A + 夜班补贴 × N + 学班补贴 × S
   （每个班次补贴由用户自行设置，默认 0）

3. 假设分析：多上 X 天某班次（用户可选班次类型）
   → +X × 该班次补贴
```

**技术约束**：

* 纯 domain 层计算，复用 `countShiftTypeInMonth()` 统计班次
* 津贴配置使用 `Double` 类型（支持小数），持久化到 DataStore（1 个 key，序列化格式 `"MORNING=12.5,..."`)
* 支持自定义周期和参考日期
* 当月班次统计随班组切换自动更新

### 2.9 图片分享（社交传播功能）

**功能**：将同事模式的共同休息结果转化为一张精美的分享长图（1080px 宽，含二维码），通过系统原生分享面板发送到微信、QQ 等第三方应用。首期仅覆盖同事模式。

**核心价值**：同事模式"下次同时休息：5月28日"本身是天然对话素材。用户截图分享 → 接收方看到具体日期 + 二维码 → 扫码下载 App → 产生裂变传播。分享图是社交传播的载体，不是简单的"导出图片"功能。

**交互流程**：

1. 用户在同事模式结果页点击分享按钮（TopAppBar 右侧 Share 图标）
2. 按钮变为 loading 动画（`isSharing = true`）
3. 后台异步渲染（`Dispatchers.Main` 离屏 ComposeView → `Dispatchers.IO` 写文件）
4. 生成完成后自动弹出系统分享面板（`Intent.ACTION_SEND` + `image/png`）
5. 用户选择微信/QQ 等目标 App 发送
6. 发送完成后页面恢复（`shareUri` 重置为 null）

**分享图技术参数**：

| 参数 | 值 |
|------|-----|
| 输出格式 | PNG（无损，文字清晰） |
| 宽度 | 1080px（360dp × 3x 密度） |
| 高度 | 约 1920px（内容自适应） |
| 设计语言 | V2 Dark Productivity Design |
| QR 码 | 200×200dp，`SHARE_QR_URL` 常量指向 `https://www.bilibili.com`（上架后替换为应用商店链接） |
| 文件位置 | `cacheDir/share_images/colleague_{timestamp}.png` |
| 分享 Uri | `content://com.simpleshift.scheduler.fileprovider/share_images/...`（FileProvider 授权） |

**安全与内存**：

* FileProvider `exported="false"` + `grantUriPermissions="true"` + `FLAG_GRANT_READ_URI_PERMISSION`：仅目标 App 获得临时读取权限
* 缓存清理：App 启动 + 每次分享前清理 24h 前文件
* 内存管理：渲染前检查可用内存，Bitmap 用完及时 `recycle()`
* 异常处理：FileProvider Uri 生成失败 / 目标 App 拒绝接收 → try-catch + Snackbar 提示用户

**二维码 URL 管理**：

* 常量 `SHARE_QR_URL` 集中在 `domain/qr_code_generator.kt` 顶部
* 当前占位 `https://www.bilibili.com`
* 上架后改为应用商店链接（如 `https://play.google.com/store/apps/details?id=com.simpleshift.scheduler` 或各品牌应用商店落地页）
* 后续可接入 Firebase Remote Config 或自身 API 实现远程切换，无需发版
