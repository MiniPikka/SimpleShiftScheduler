# Part A：CP（Cross Platform）版设计文档

## A.1 项目定位

倒班助手不再是单纯的 Android 工具 App。CP 版本目标是成为**倒班人群的生活助手**——高频、情绪价值、社交传播。

### 平台目标

- Android
- iOS
- Web（后期）
- Desktop（后期）

统一业务逻辑与视觉语言。

---

## A.2 CP 版本核心目标

### A.2.1 真正的跨平台产品

重点不再是 Android API 深度适配。重点变为：产品体验、用户增长、社交传播、多端一致性、快速迭代。

### A.2.2 UI 一致性

所有平台保持统一：卡片语言、动画风格、颜色系统、排版体系、交互逻辑。采用统一 Design System。

### A.2.3 算法中心化

核心竞争力——倒班算法、拼假算法、同事模式算法、津贴统计、工作强度分析——全部抽离为纯 Domain 层。UI 可重构，算法必须稳定。

班组设置、周期设置、提醒设置、数据备份、多设备同步（后期）、主题切换、语言切换。

## A.5 CP 架构原则

### A.5.1 UI 与业务彻底解耦

UI：Flutter Widget + 页面状态 + 动画。Domain：排班算法、拼假算法、日期计算、统计逻辑——全部纯函数化，无平台依赖、无 UI 依赖、无生命周期依赖。

### A.5.2 平台能力抽象

通知、Widget、分享、本地存储、权限——全部通过抽象接口实现。

### 2.4 日历提醒

**功能**：为每个班次类型设置独立的提醒时间，通过系统日历日程实现。

**界面元素**：

* 提醒设置在设置页"倒班规则设置"中，位于班组选择下方
* 每个班次类型（早/中/休/夜/学）一行，显示当前提醒时间或"未设置"
* 点击行弹出 Material3 `TimePicker` 时钟表盘（24 小时制，V2 Design Token 主题一致）
* 已设置提醒的班次可点击"关闭提醒"按钮（红色）删除

**提醒策略**：

* 使用 Android Calendar Provider（`CalendarContract`）写入设备本地日历日程
* 每次设置变更后自动同步未来 365 天（一整年）的日历日程
* 日程持久化在系统日历数据库，设备重启自动恢复
* 应用回到前台时重新同步（处理时区变更）
* 使用默认班组计算班次日期
* 每个日程设置准时提醒（`METHOD_ALERT`），系统自动弹出通知
* 使用本地日历账户（`ACCOUNT_TYPE_LOCAL`），日程不依赖 Google 账户、不同步云端

**跨品牌兼容性**：

* Calendar Provider 是 AOSP 标准 API（API 14+），所有 Android 品牌必须支持
* 小米 MIUI、华为 EMUI/HarmonyOS、OPPO ColorOS、Vivo OriginOS、三星、原生 Android 全兼容

**权限需求**：

* `READ_CALENDAR`：读取系统日历（查询现有日程）
* `WRITE_CALENDAR`：写入/修改系统日历日程

* **今日班次徽章**：圆角 10dp Box + 班次强调色背景 + 20sp Bold 白字（早=橙 `#FFB347`、中=蓝 `#4DA3FF`、休=绿 `#35D07F`、夜=紫 `#7C5CFF`、学=黄 `#F2D94E`）

**交互**：

* 点击 Widget 任意位置 → 打开 App 首页
* Widget 每 1 小时自动刷新
* App 内修改设置后 Widget 立即更新（含快照比较去重：设置未变化时跳过更新）

**技术方案**：

* 使用 Jetpack Glance 框架（Compose 式 Widget API）
* 直接从 DataStore 读取倒班配置，调用 domain 层 `computeWidgetShiftData()` 计算今日数据 + 明日数据
* 颜色以 `Color(0xFFxxxxxx)` 内联在 `ShiftWidget.kt` 中（Glance 不支持资源引用和主题系统）
* 进度使用纯文字"第 X/Y 天"（Glance 不支持 `LinearProgressIndicator`、`fillMaxWidth(fraction)` 等 Compose 特性）
* 徽章使用 `Box` + `cornerRadius(10.dp)` + `background(accentColor)`（Glance 无 `CircleShape`）
* 实例复用：`ShiftWidget` 作为 Activity 的 `val` 单例，避免每次更新的对象分配
* 无需额外后台服务，利用系统 Widget 更新机制

### 2.6 拼假神器（差异化核心功能）

**功能**：自动分析今日至年底的最佳请假方案，结合用户的倒班表 + 法定节假日，找到"请最少假、连休最久"的策略。不跨年，日期显示清晰无歧义。

**核心价值**：倒班人员的妻儿老小遵循正常节假日作息。拼假神器帮助用户用最少的年假，在家人放假时最大化团聚时间。

**界面结构**：

```
│  │ 请假 2 天 → 连休 6 天          │    │  (金色边框)
│  │ 6月15日 — 6月20日              │    │
│  │ 含端午节假期 🎋                 │    │  节日标识
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 1 天 → 连休 4 天          │    │  常规策略卡片
│  │ 5月16日 — 5月19日              │    │  (按效率降序)
│  │ 含周末                         │    │
│  │ 效率: 4.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 3 天 → 连休 9 天          │    │
│  │ 9月30日 — 10月8日              │    │
│  │ 含国庆节假期 🏛                │    │
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│  ...                                 │
└──────────────────────────────────────┘
```

**界面元素**：

* **顶部说明区**：简短说明功能用途（基于倒班表 + 法定节假日）
* **策略卡片列表**（按综合评分降序）：
  * 请假天数 → 连休天数（大字体，核心信息）
  * 具体日期范围：连休起止日
  * 节日/周末重叠标识（如"含端午节假期 🎋"、"含周末"）
  * 效率标签（连休 ÷ 请假 = X倍）
  * 最佳方案卡片有金色边框高亮
* **筛选选项**（可选，二期）：
  * 最多请假天数滑块（默认 5 天）
  * 仅看含节假日方案 toggle

**算法核心逻辑**：

1. 生成未来 365 天每日状态（班休 + 节假日 + 周末）
2. 识别所有"休息块"（连续休班日）和"工作间隙"（两块休息之间的连续工作日）
3. 对于每个 ≤ 最大请假天数的工作间隙：请假桥接 → 两边休息块 + 间隙 = 一个长连休
4. 额外检测：请假延伸现有休息块（在休息块前后请 1~N 天）
5. 综合评分：
   - 效率分：连休天数 ÷ 请假天数（权重 50%）
   - 长度分：连休绝对长度（权重 25%）
   - 家庭分：与节假日/周末的重叠天数（权重 25%）
6. 去重（同一连休区间的策略保留最优）、按评分降序排列

**法定节假日数据**：

* 内置中国国务院发布的法定节假日（元旦、春节、清明、劳动节、端午、中秋、国庆）
* 包含调休工作日（如周末补班），确保计算准确
* 数据文件 `domain/holiday_data.kt`，每年更新一次
* **分析范围**：今日至当年 12 月 31 日（不跨年，避免年份混淆）

**技术约束**：

* 纯 domain 层计算（所有函数可独立单元测试）
* 不依赖网络请求（节假日数据本地内置）

### 2.8 倒班津贴（高频刚需功能）

**功能**：输入各班次补贴金额（早/中/夜/学各可设），自动统计当月各班次天数，精确计算本月倒班津贴。支持"如果多上 X 天某班次"的假设分析。只算倒班直接决定的收入——算得准、零维护、普适所有企业。

**核心价值**：倒班津贴是唯一完全由倒班表决定的收入。用户每次换班/加班前都会想"这样能多拿多少"，打开 App 就能看到答案。高频刚需，计算 100% 准确。

**界面结构**：

```

├──────────────────────────────────────┤

│  班次补贴（每班额外金额）               │
│  早班 [0]   中班 [50]                 │
│  夜班 [200] 学班 [0]  元/班           │
├──────────────────────────────────────┤
│  5月 · 一值                           │  当前统计月
│                                      │
│       本月倒班津贴                     │
│       ¥1,750                          │  大字体金额
│                                      │
│  班次统计                             │
│  早班 8次 · 中班 7次 · 夜班 7次       │
│  休班 8次 · 学班 1次                  │
│  夜班 ¥1,400 · 中班 ¥350             │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 💡 如果多上 [2] 天 [夜班 ▼]    │    │  假设分析
│  │ → 津贴 +¥400                  │    │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘
```

**界面元素**：

* **津贴设置区**（可折叠）：
  * 班次补贴：早/中/夜/学各一行，每班额外金额（默认全 0，支持小数如 12.5 元）
  * 输入支持小数点（整数部分最多 4 位，小数部分最多 2 位）
  * 部分输入（如 "5."）不会丢失——显示文本与解析值解耦，保持编辑流畅
* **当月津贴主卡片**：
  * 大字体"本月倒班津贴"金额（核心视觉焦点）
* **班次统计区**：
  * 自动统计当月各班次天数（从倒班表计算）
  * 各班次贡献明细（夜班 7次 × ¥200 = ¥1,400 · 中班 7次 × ¥50 = ¥350）
* **假设分析卡片**：
  * 天数和班次类型均可选
  * 实时显示津贴增量

**算法**：

```
1. 统计当月各班次天数：
   早班 M 次、中班 A 次、夜班 N 次、休班 R 次、学班 S 次

2. 本月倒班津贴 =
   早班补贴 × M + 中班补贴 × A + 夜班补贴 × N + 学班补贴 × S
   （每个班次补贴由用户自行设置，默认 0）

3. 假设分析：多上 X 天某班次（用户可选班次类型）
   → +X × 该班次补贴
```

**技术约束**：

* 纯 domain 层计算，复用 `countShiftTypeInMonth()` 统计班次
* 津贴配置使用 `Double` 类型（支持小数），持久化到 DataStore（1 个 key，序列化格式 `"MORNING=12.5,..."`)
* 支持自定义周期和参考日期
* 当月班次统计随班组切换自动更新

# Part C：产品愿景 — 班伴 / ShiftMate（2026-05-22 起）

## C.1 产品定位升级

倒班助手不再是单纯的"跨平台 App"。从 2026-05-22 起，产品品牌升级为：

> **班伴（英文名 ShiftMate）—— 倒班人群的生活伴侣**

产品名"班伴"：自然、有陪伴感、好记、不装。英文名 ShiftMate 用于国际化场景（应用商店、GitHub org、crates.io）。

核心理念变化：

| 以前 | 现在 |
|------|------|
| 做一个 App | 做一个生态系统 |
| 跨平台 UI 一致 | 协议标准一致 |
| 功能越多越好 | 融入操作系统越深越好 |
| 用户打开 App 使用 | 用户抬眼就能看到信息 |
| 自建通知系统 | 借力系统日历生态 |
| 移动端为主 | Linux 重度用户 + 移动端并存 |

## C.2 设计原则

### C.2.1 倒班信息是 Glanceable Info

用户不需要"打开软件"来看今天什么班。倒班信息应该像时间、天气一样，抬头就能看到：
- 状态栏/桌面 Widget 显示今日班次
- 系统日历自动标记每个日期班次
- 通知在提醒时间弹出

### C.2.2 协议 > App

ICS (RFC 5545) 是日历数据交换的世界语。生成一个标准的 `.ics` 文件，胜过在 10 个平台上写 10 个 UI。自动兼容 Thunderbird、KDE Calendar、GNOME Calendar、Evolution、Nextcloud、Apple Calendar、Google Calendar、Outlook。

### C.2.3 CLI 是工程师的入口

Linux 用户天然喜欢命令行。`banban today` 比打开 App 查看快得多。CLI 也是自动化（cron/systemd timer）和脚本集成的基础。

### C.2.4 本地优先，云可叠加

数据所有权在用户手中。ICS 文件在本地，配置文件在 ~/.config，CalDAV 同步到自己的 Nextcloud。后期可选 Supabase 云同步，但绝不强制。

| **CLI 层** | Linux 工程师 | 快速查询、自动化 | `banban` 命令 |
| **桌面层** | Linux Desktop 用户 | 抬眼看到班次 | Plasma Widget / Waybar |

## C.4 新增产品功能设计

### C.4.1 ICS/CalDAV 日历导出

**功能**：生成标准 `.ics` 文件，包含完整排班表、RRULE 周期规则、VALARM 提醒设置。

**使用方式**：
```bash
banban export --ics --output ~/my_shift_schedule.ics
# 然后在 Thunderbird/KDE Calendar/Nextcloud 中导入此文件
```

**设计要点**：
- RRULE 压缩：42 天周期 → 6 个 VEVENT（每种不同班次+班组组合一个）
- 时区：明确标注 Asia/Shanghai（UTC+8）
- VALARM：使用用户配置的提醒时间，提前 N 分钟触发
- 夜班跨日：夜班按结束日标记，DTSTART 为前一晚 22:00，DTEND 为标记日早上 08:00（与夜班提醒提前一天同一约定）
- 节假日覆盖：法定节假日用 EXDATE 排除，调休工作日覆盖为实际班次

### C.4.2 CLI 工具

**功能**：命令行查询倒班信息，面向 Linux 工程师用户。

**命令矩阵**：

```bash
banban today              # 今日班次
banban tomorrow           # 明日班次
banban week               # 本周 7 天视图 (v0.1.3)
banban next-rest          # 距下次休息倒计时
banban calendar           # 当月日历（ANSI 颜色）
banban calendar -m 2026-06  # 指定月份
banban stats              # 本月统计（早/中/休/夜/学）
banban leave              # 拼假推荐 Top 5
banban leave --max-days 3 # 限制最多请假天数
banban colleague 1 3      # 班组1和3共同休息日
banban export --ics       # 导出 ICS
banban waybar             # Waybar 状态栏输出
banban notify             # 桌面通知
banban install            # 安装 systemd 定时器
banban tui                # 全屏终端 UI
banban config             # 管理配置
```

**设计要点**：
- 默认人类可读输出（ANSI 颜色：早=橙、中=蓝、休=绿、夜=紫、学=黄）
- `--json` 全局 flag 输出机器可读 JSON
- `--lang zh/en` 全局 flag 切换中英文
- `--team N` 指定班组
- 配置文件：`~/.config/banban/config.toml`（XDG 规范）
- 数据输出：`~/.local/share/banban/`（XDG 规范）
- Shell 自动补全：bash/zsh/fish/nushell

### C.4.3 KDE Plasma Widget

**功能**：在 KDE 桌面/状态栏显示今日班次信息，用户抬眼即见。

### C.4.4 Waybar 模块

**功能**：在 Waybar（Sway/Hyprland 状态栏）显示倒班信息。

**输出格式**：

- CSS class 根据班次类型变化（morning/afternoon/rest/night/study），支持自定义颜色
- 简洁模式仅显示班次图标/文字
- tooltip 显示完整信息

### C.4.5 DBus 服务

**功能**：系统级倒班数据服务，供 Plasma Widget、通知守护进程、脚本等消费。

**接口设计**：
```
com.simpleshift.ShiftDaemon
  /com/simpleshift/Shift
    methods:
      GetTodayShift() → (s shift_type, u day, u total, i days_until_rest)
      GetShiftForDate(x date) → (s shift_type, u day, u total)
      GetUpcomingRest() → (x date, i days_until)
      GetConfig() → (u cycle_length, u default_team)
    signals:
      ShiftChanged(s new_shift_type)
      DayChanged(x new_date)
```

### C.4.6 Local HTTP API

**功能**：localhost HTTP 端点，供脚本、自动化、第三方工具消费。

**端点设计**：
```
GET  /banban             → {"today": {...}, "tomorrow": {...}}
GET  /shift/2026-06-01   → {"date": "...", "shift_type": "...", ...}
GET  /calendar/2026/05    → {"days": [...], "stats": {...}}
GET  /leave?max_days=5    → {"strategies": [...]}
GET  /colleague/1/3        → {"common_rests": [...], ...}
GET  /health               → {"status": "ok", "version": "1.0.0"}
```

- 非特权端口 11451
- 仅监听 localhost（不暴露到网络）
- JSON 响应
- CORS 允许 localhost（供浏览器扩展/TUI 使用）

## C.5 产品战略升级

### 从 App 到生态

| 维度 | 旧战略（Flutter App） | 新战略 |
|------|----------------------|-------------------|
| **目标用户** | 手机用户 | 手机用户 + Linux 工程师 + 所有日历用户 |
| **核心竞争力** | App UI 体验 | Rust 算法 + 协议标准 |
| **分发方式** | 应用商店 | 应用商店 + crates.io + AUR/PPA + ics 文件 |
| **用户增长** | ASO 优化 | 协议兼容性增长（每个日历软件都是新渠道） |
| **维护成本** | 多端 UI 同步维护 | 一个 Rust 核心 + 多个轻量前端 |
| **长期生命力** | 依赖应用商店政策 | 依赖标准协议（永远存在） |

### 关键增长渠道

1. **ICS 文件分发**：任何人都可以下载一个 `.ics` 文件导入自己的日历——这本身就是获取用户的方式
2. **crates.io**：Rust 社区发现 `banban` CLI → 安装试用
3. **AUR（Arch User Repository）**：Arch Linux 用户 `yay -S shift-cli`
4. **KDE Store**：Plasma Widget 分发
5. **应用商店**（保留）：Google Play + App Store（移动端）
