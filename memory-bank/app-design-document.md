# 倒班助手 App 设计文档

## 1. 概述

**应用名称**：倒班助手
**平台**：Android
**功能简介**：
用于帮助用户管理和查看倒班信息，支持周期设置、班组管理、日历展示及统计功能。

---

### 2.2 倒班日历

**功能**：独立页面，通过首页"📅 日历"按钮跳转进入。按日历展示本月倒班情况，可切换班组并统计班次数量。

**界面结构**：
- 顶部 TopAppBar（返回箭头 + 标题"倒班日历"）
- 班组下拉框
- 月份导航栏（上月/下月 + 今天按钮 + 统计按钮）

**界面元素**：

* **7×7 日历表**：

  * 第一行显示周日到周六
  * 其余行显示当前月日期及补全的前月/下月日期
  * 每个格子包含两行：

    1. 日期
    2. 班次类型（早、中、休、夜、学习班）
* **左上角班组切换下拉框**：用于切换不同班组
* **右上角统计按钮**：统计当前班组在当月早、中、休、夜、学习班的天数

### 2.4 日历提醒

**功能**：为每个班次类型设置独立的提醒时间，通过系统日历日程实现。

**界面元素**：

* 提醒设置在设置页"倒班规则设置"中，位于班组选择下方
* 每个班次类型（早/中/休/夜/学）一行，显示当前提醒时间或"未设置"
* 点击行弹出时间选择对话框（时/分输入）
* 已设置提醒的班次可点击"关闭此班次提醒"删除

**提醒策略**：

* 使用 Android Calendar Provider（`CalendarContract`）写入设备本地日历日程
* 每次设置变更后自动同步未来 365 天（一整年）的日历日程
* 日程持久化在系统日历数据库，设备重启自动恢复
* 应用回到前台时重新同步（处理时区变更）
* 使用默认班组计算班次日期
* 每个日程设置准时提醒（`METHOD_ALERT`），系统自动弹出通知
* 使用本地日历账户（`ACCOUNT_TYPE_LOCAL`），日程不依赖 Google 账户、不同步云端

**跨品牌兼容性**：

* Calendar Provider 是 AOSP 标准 API（API 14+），所有 Android 品牌必须支持
* 小米 MIUI、华为 EMUI/HarmonyOS、OPPO ColorOS、Vivo OriginOS、三星、原生 Android 全兼容

**权限需求**：

* `READ_CALENDAR`：读取系统日历（查询现有日程）
* `WRITE_CALENDAR`：写入/修改系统日历日程

* 距休天数（=0 显示绿色"休息日"，>0 显示"距休 X天"）

* 进度使用纯文字"第 X/Y 天"（Glance 不支持 `LinearProgressIndicator`、`fillMaxWidth(fraction)`、`defaultWeight()` 加权比例）
* 徽章使用 `Box` + `cornerRadius(12.dp)` + `background(accentColor)`（Glance 无 `CircleShape`）
* 无需额外后台服务，利用系统 Widget 更新机制

### 2.6 拼假神器（差异化核心功能）

**功能**：自动分析今日至年底的最佳请假方案，结合用户的倒班表 + 法定节假日，找到"请最少假、连休最久"的策略。不跨年，日期显示清晰无歧义。

**核心价值**：倒班人员的妻儿老小遵循正常节假日作息。拼假神器帮助用户用最少的年假，在家人放假时最大化团聚时间。

**界面结构**：

```
┌──────────────────────────────────────┐
│  ← 拼假神器                           │  TopAppBar
├──────────────────────────────────────┤
│  基于你的倒班表 + 法定节假日             │  说明文字
│  帮你找到最佳请假方案                    │
├──────────────────────────────────────┤
│  ┌──────────────────────────────┐    │
│  │ 🏆 最佳方案                    │    │  高亮推荐卡片
│  │ 请假 2 天 → 连休 6 天          │    │  (金色边框)
│  │ 6月15日 — 6月20日              │    │
│  │ 含端午节假期 🎋                 │    │  节日标识
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 1 天 → 连休 4 天          │    │  常规策略卡片
│  │ 5月16日 — 5月19日              │    │  (按效率降序)
│  │ 含周末                         │    │
│  │ 效率: 4.0x                     │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 请假 3 天 → 连休 9 天          │    │
│  │ 9月30日 — 10月8日              │    │
│  │ 含国庆节假期 🏛                │    │
│  │ 效率: 3.0x                     │    │
│  └──────────────────────────────┘    │
│  ...                                 │
└──────────────────────────────────────┘
```

**界面元素**：

* **顶部说明区**：简短说明功能用途（基于倒班表 + 法定节假日）
* **策略卡片列表**（按综合评分降序）：
  * 请假天数 → 连休天数（大字体，核心信息）
  * 具体日期范围：连休起止日
  * 节日/周末重叠标识（如"含端午节假期 🎋"、"含周末"）
  * 效率标签（连休 ÷ 请假 = X倍）
  * 最佳方案卡片有金色边框高亮
* **筛选选项**（可选，二期）：
  * 最多请假天数滑块（默认 5 天）
  * 仅看含节假日方案 toggle

**算法核心逻辑**：

1. 生成未来 365 天每日状态（班休 + 节假日 + 周末）
2. 识别所有"休息块"（连续休班日）和"工作间隙"（两块休息之间的连续工作日）
3. 对于每个 ≤ 最大请假天数的工作间隙：请假桥接 → 两边休息块 + 间隙 = 一个长连休
4. 额外检测：请假延伸现有休息块（在休息块前后请 1~N 天）
5. 综合评分：
   - 效率分：连休天数 ÷ 请假天数（权重 50%）
   - 长度分：连休绝对长度（权重 25%）
   - 家庭分：与节假日/周末的重叠天数（权重 25%）
6. 去重（同一连休区间的策略保留最优）、按评分降序排列

**法定节假日数据**：

* 内置中国国务院发布的法定节假日（元旦、春节、清明、劳动节、端午、中秋、国庆）
* 包含调休工作日（如周末补班），确保计算准确
* 数据文件 `domain/holiday_data.kt`，每年更新一次
* **分析范围**：今日至当年 12 月 31 日（不跨年，避免年份混淆）

**技术约束**：

* 纯 domain 层计算（所有函数可独立单元测试）
* 不依赖网络请求（节假日数据本地内置）
* 支持自定义周期和参考日期（复用现有 `customCycle` + `referenceDate`）

### 2.7 同事模式（社交裂变功能）

**功能**：输入两个人的班组，自动计算下次同时休息日期、共同休息天数。情侣、朋友、同事都会用，传播力极强。

**核心价值**：不同班组的倒班人员休息日不同。同事模式让两个人一眼看到"我们什么时候能一起休息"，解决社交协调痛点。结果截图即内容，天然适合社交传播。

**界面结构**：

```

├──────────────────────────────────────┤

│                                      │
├──────────────────────────────────────┤
│  ┌──────────────────────────────┐    │
│  │       下次同时休息               │    │  主结果卡片
│  │         5月28日                 │    │  大字体日期（36sp Bold）
│  │         星期三                  │    │
│  │       距今 14 天                │    │
│  └──────────────────────────────┘    │
│                                      │
│  ┌────────────┬────────────┐         │
│  │ 未来30天    │ 未来60天    │         │  统计卡片行
│  │  共同休息   │  共同休息    │         │

│  ┌──────────────────────────────┐    │
│  │ 5月28日 星期三               │    │
│  │ 6月03日 星期二               │    │
│  │ ...                          │    │
│  └──────────────────────────────┘    │
│  分析范围：2026/05/14 — 12/31         │
└──────────────────────────────────────┘
```

**界面元素**：

* **双班组选择区**：两个并排下拉框（"我是"和"他是"），切换即时刷新
* **主结果卡片**（核心视觉焦点）：大字体"下次同时休息"日期 + 星期 + 倒计时，渐变背景
* **统计卡片行**：未来 30/60 天共同休息次数
* **共同休息日列表**：可滚动日期列表，每行显示日期 + 星期
* **底部**：分析范围说明（今日至年底）

**算法**：

对分析范围内每一天，分别计算两个人的班次：
```
isRestA = (shiftA == REST || shiftA == STUDY)
isRestB = (shiftB == REST || shiftB == STUDY)
if isRestA && isRestB → 共同休息日
```
O(n)，n ≤ 365。纯函数，可独立单元测试。复用 `getShiftTypeForDate()` 和 `teamPhaseOffsetFor()`。

**社交传播设计**：

* "下次同时休息"是大字体具体日期，天然对话素材（"我们 5 月 28 日可以一起休息！"）
* 结果页面信息密度高，截图即社交分享内容
* 两个人一起看屏幕时，主卡片视觉冲击力强
* V2 可加入分享按钮（生成带二维码的分享图）

**技术约束**：

* 纯 domain 层计算，复用 `getShiftTypeForDate()` + `teamPhaseOffsetFor()`
* 分析范围：今日至当年 12 月 31 日（与拼假神器一致，不跨年）
* 班组下拉框复用 `TeamDropdown` 组件

### 2.8 倒班津贴（高频刚需功能）

**功能**：输入各班次补贴金额和餐补，自动统计当月各班次天数，精确计算本月倒班津贴和餐补合计。每种班次（早/中/夜/学）可单独设置补贴金额，支持"如果多上 X 天某班次"的假设分析。只算倒班直接相关的收入，不涉及基本工资、五险一金、个税等企业差异化部分——算得准、维护简单、用户一看就懂。

**核心价值**：倒班津贴是唯一由倒班表直接决定的收入。用户每次换班/加班前都会想"这样能多拿多少"，打开 App 就能看到答案。高频刚需，计算准确。

**界面结构**：

```
┌──────────────────────────────────────┐
│  ← 倒班津贴                           │  TopAppBar
├──────────────────────────────────────┤
│  ⚙️ 津贴设置                          │  可折叠设置区
│  班次补贴（每班额外金额）               │
│  早班 [0]   中班 [50]                 │
│  夜班 [200] 学班 [0]  元/班           │
│  餐补: [50] 元/班  折扣: [0.85]       │
├──────────────────────────────────────┤
│  5月 · 一值                           │  当前统计月
│                                      │
│       本月倒班津贴                     │
│       ¥2,350                          │  大字体金额
│                                      │
│  ┌────────┬────────┬────────┐        │
│  │ 班次补贴│ 餐补合计 │ 总计    │        │  三宫格
│  │ ¥1,750 │  ¥526  │ ¥2,276 │        │
│  └────────┴────────┴────────┘        │
│                                      │
│  班次统计                             │
│  早班 8次 · 中班 7次 · 夜班 7次       │
│  休班 8次 · 学班 1次                  │
│  夜班贡献 ¥1,400 · 中班贡献 ¥350      │
│                                      │
│  ┌──────────────────────────────┐    │
│  │ 💡 如果多上 [2] 天 [夜班 ▼]    │    │  假设分析
│  │ → 津贴 +¥400                  │    │
│  └──────────────────────────────┘    │
└──────────────────────────────────────┘
```

**界面元素**：

* **津贴设置区**（可折叠）：
  * 班次补贴：早/中/夜/学各一行，每班额外金额（默认全 0）
  * 餐补金额 + 变现折扣率（0~1.0，默认 1.0）
* **当月津贴主卡片**：
  * 大字体"本月倒班津贴"金额（核心视觉焦点）
  * 三宫格：班次补贴合计 / 餐补合计 / 总计
* **班次统计区**：
  * 自动统计当月各班次天数（从倒班表计算）
  * 各班次贡献明细（如 夜班贡献 ¥1,400 · 中班贡献 ¥350）
* **假设分析卡片**：
  * 天数和班次类型均可选
  * 实时显示津贴增量

**算法**：

```
1. 统计当月各班次天数：
   早班 M 次、中班 A 次、夜班 N 次、休班 R 次、学班 S 次
   工作天数 = M + A + N + S

2. 班次补贴合计 =
   早班补贴 × M + 中班补贴 × A + 夜班补贴 × N + 学班补贴 × S
   （每个班次补贴由用户自行设置，默认 0）

3. 餐补合计 = 餐补 × 工作天数 × 变现折扣率

4. 本月倒班津贴 = 班次补贴合计 + 餐补合计

5. 假设分析：多上 X 天某班次（用户可选班次类型）
   → +X × (该班次补贴 + 餐补 × 折扣率)
```

**技术约束**：

* 纯 domain 层计算，复用 `countShiftTypeInMonth()` 统计班次
* 津贴配置持久化到 DataStore（SettingsRepository 新增 key）
* 支持自定义周期和参考日期
* 当月班次统计随班组切换自动更新
* 不涉及基本工资、五险一金、个税等——只算倒班直接决定的收入

## 3. 数据结构设计（简要）

* **班组信息**

```json
{
  "group_id": 1,
  "name": "班组1",
  "shift_cycle": ["早","早","中","中","休","夜","夜", ...] // 42天
}
```

* **日历数据**

```json
{
  "date": "2026-04-26",
  "shift": "早"
}
```

* **统计数据**

```json
{
  "early": 10,
  "mid": 8,
  "rest": 12,
  "night": 8,
  "study": 4
}
```

* **闹钟设置**

```json
{
  "MORNING": "06:00",
  "AFTERNOON": "14:00",
  "REST": null,
  "NIGHT": "22:00",
  "STUDY": null
}
```

* **节假日信息**

```json
{
  "date": "2026-06-19",
  "name": "端午节",
  "isHoliday": true
}
```

* **请假策略**

```json
{
  "leaveDays": 2,
  "totalBreakDays": 6,
```

## 5. 其他说明

* 支持多班组管理
* 支持自定义倒班规则
* 支持周期循环与跨月显示
* 提供当月班次统计功能
* 首页日期展示要求为“本地化可读”即可（不强制固定格式）
* 日期计算使用设备本地时区，基于 `LocalDate.now()` 即时生效
* 拼假神器：结合倒班表 + 法定节假日，自动分析最佳请假方案（差异化核心功能）
* 同事模式：输入两人班组，自动计算共同休息日（社交裂变功能）
* 倒班津贴：输入各班次补贴和餐补，自动统计班次并计算本月津贴（高频刚需功能）
